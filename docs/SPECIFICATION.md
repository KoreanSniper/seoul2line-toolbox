# ============================================================
# MASTER SPECIFICATION v1
# Real-Time Nation Sandbox Strategy Game
# ============================================================

이 문서는 현재 프로젝트에 적용할 게임 시스템의 1차 마스터 명세이다.

이 문서에서 명시한 규칙은 프로젝트의 기본 규칙으로 취급한다.

중요:
- 명세에 없는 시스템을 임의로 만들어내지 마라.
- 기존에 정상적으로 작동하는 시스템을 이유 없이 다시 작성하지 마라.
- 구현에 필요한 정보가 명확하지 않으면 추측하지 말고 TODO로 남겨라.
- 기존 프로젝트 구조를 먼저 분석한 뒤 최소한의 변경으로 기능을 추가하라.
- "더 좋아 보인다", "일반적으로 게임은 이렇게 한다" 등의 이유로 설계를 임의 변경하지 마라.


============================================================
0. 가장 중요한 전제
============================================================

현재 프로젝트의 월드 생성 시스템은 이미 완성되어 있다.

월드 생성기는 수정 대상이 아니다.

현재 월드에는 이미 다음 요소가 정상적으로 생성된다.

- 큰 섬
- 바다
- 산맥
- 산
- 계곡
- 평야
- 호수
- 해안
- 반도
- 기타 자연 지형
- 8개의 수도 위치를 나타내는 깃발

현재 생성되는 지형의 품질과 형태는 만족스러운 상태이다.

따라서 절대로 월드 생성 시스템을 새로 만들거나
단순화하거나 교체하거나 대규모 수정하지 마라.


============================================================
1. 절대 수정 금지 영역
============================================================

다음 요소는 특별한 요청이 없는 한 수정하지 않는다.

- terrain generation algorithm
- mountain generation
- coastline generation
- lake generation
- island shape generation
- terrain noise
- world seed 처리 방식
- terrain mesh 생성 방식
- 현재 정상적으로 작동하는 terrain rendering
- 현재 수도 깃발의 위치
- 기존 월드 크기
- 기존 월드 생성 결과의 전체적인 모습

DO NOT REBUILD THE WORLD GENERATOR.

The current world generation system is considered finished.

Treat the generated world as INPUT DATA for the strategy game.


게임 시스템은 기존 지형에서 다음 정보를 읽을 수 있다.

- world position
- terrain elevation
- terrain normal
- slope
- land / water 여부
- collision
- shoreline
- navigation 가능 여부

그러나 이런 정보를 얻기 위해 월드 생성기를 새로 만들면 안 된다.


============================================================
2. 게임의 정체성
============================================================

이 게임은 단순한 전통 RTS가 아니다.

게임의 기본 장르는:

REAL-TIME NATION SANDBOX STRATEGY

이다.

다음 요소들이 결합된다.

- 실시간 전략
- 국가 운영
- 도시 건설
- 군대 운용
- 외교
- 전쟁
- 기반시설 건설
- 영토 확장
- 샌드박스 플레이


게임에는 총 8개의 국가가 존재한다.

각 국가에는 수도가 하나씩 존재한다.

현재 월드의 8개 깃발 위치가 각 국가의 수도 위치이다.


플레이어는 국가 하나를 조종한다.

나머지 국가는 AI가 조종한다.


============================================================
3. 게임의 목표
============================================================

이 게임은 반드시 다른 국가를 모두 уничтожить 해야 하는
전형적인 RTS가 아니다.

강제된 단일 승리 조건을 기본 게임플레이의 중심으로 두지 않는다.

플레이어는 원하는 방식으로 국가를 운영할 수 있다.

예:

- 도시를 성장시킨다.
- 건물을 건설한다.
- 도로를 만든다.
- 항구를 만든다.
- 군대를 만든다.
- 다른 국가와 평화롭게 지낸다.
- 동맹을 맺는다.
- 무역한다.
- 국경을 방어한다.
- 전쟁을 선포한다.
- 다른 국가를 침공한다.
- 경제 중심 국가를 만든다.
- 군사 중심 국가를 만든다.

게임의 핵심은:

"8개의 국가가 하나의 세계에서 실시간으로 성장하고
서로 상호작용하는 샌드박스"

이다.

============================================================
5. 게임 세계의 물리적 의미
============================================================

현재 생성된 지형은 단순한 배경이 아니다.

지형은 실제 게임플레이에 영향을 준다.

반드시 다음 원칙을 지켜야 한다.

VISIBLE TERRAIN == GAMEPLAY TERRAIN


화면에 산이 있다면 실제로 산이어야 한다.

화면에 호수가 있다면 실제로 물이어야 한다.

화면에 절벽이 있다면 실제 이동 장애물이어야 한다.


============================================================
6. 산
============================================================

산은 실제 이동 장애물이다.

유닛이 산 내부를 통과해서는 안 된다.

다음과 같은 이동은 절대 금지한다.

START
   |
   |
[ MOUNTAIN ]
   |
   |
TARGET

↓

START -> mountain interior -> TARGET


대신 유닛은:

- 산을 우회하거나
- 실제 통과 가능한 계곡을 이용하거나
- 실제 통과 가능한 완만한 고개를 이용한다.


현재 게임에는 터널 시스템이 정의되어 있지 않다.

따라서:

산 내부를 통과하는 이동 = 불가능

으로 취급한다.


============================================================
7. 경사
============================================================

모든 육상 유닛은 최대 이동 가능한 경사를 가진다.

기본 개념:

낮은 경사
→ 정상 이동

중간 경사
→ 이동 가능
→ 이동 속도 감소 가능

높은 경사
→ 이동 불가


구체적인 최대 경사값은
현재 월드 스케일과 terrain 데이터를 분석한 뒤
합리적인 값으로 설정해야 한다.

단:

유닛이 거의 수직인 산을 걸어 올라가면 안 된다.


============================================================
8. 절벽
============================================================

절벽은 이동 불가능 지형이다.

유닛은 절벽을:

- 순간적으로 올라가지 않는다.
- 순간적으로 내려가지 않는다.
- 벽처럼 타고 올라가지 않는다.
- 충돌로 튕겨 올라가지 않는다.


============================================================
9. 물
============================================================

육상 유닛은 물을 걸어서 건너지 못한다.

다음 지역은 육상 유닛에게 기본적으로 이동 불가이다.

- 바다
- 호수
- 깊은 수역


육상 ↔ 해상 이동은
향후 항구 및 해상 시스템을 통해 연결한다.


============================================================
10. 유닛 이동 시스템
============================================================

유닛은 단순히 목표 좌표 방향으로 직진하면 안 된다.

금지:

position += direction * speed


이것만으로 이동 시스템을 구현하지 마라.


실제 이동은 다음을 고려해야 한다.

- terrain
- slope
- water
- mountain
- cliff
- obstacle
- building
- 다른 unit
- 갈 수 있는 route


유닛이 목표 위치까지 갈 수 없다면:

"이동 불가능"

상태를 반환한다.

억지로 직선으로 이동하거나
지형을 뚫고 가지 않는다.


============================================================
11. Pathfinding
============================================================

PLAYER와 AI 모두 같은 pathfinding 시스템을 사용한다.

AI용 직선 이동 코드를 따로 만들지 마라.


Pathfinding은 최소한 다음 지형을 구분해야 한다.

WALKABLE

- 평지
- 완만한 언덕
- 통과 가능한 계곡

CONDITIONAL

- 중간 경사
- 좁은 통로

BLOCKED

- 매우 가파른 산
- 절벽
- 바다
- 호수
- 건물
- 기타 이동 불가능 영역


============================================================
12. 지면 추종
============================================================

유닛은 지형 표면을 따라 이동한다.

그러나 단순히 매 프레임:

unit.y = terrainHeight(x, z)

만 수행해서는 안 된다.

그 방식은 절벽이나 가파른 산을 순간적으로 올라가는 문제가 발생할 수 있다.


반드시 이동 가능한 경사인지 먼저 검사한다.


============================================================
13. 유닛 물리
============================================================

이 게임은 전략 게임이다.

유닛 이동에 과도한 rigidbody physics를 사용하지 마라.

특히 다음 상황은 절대로 발생해서는 안 된다.

- 산에 부딪혀 튕김
- 산에 몸을 비비면 가속
- 점프하면서 산에 부딪혀 부스팅
- 충돌 후 수십~수백 미터 날아감
- 다른 유닛과 부딪혀 공중으로 날아감
- 유닛이 계속 떨림
- 경사면에서 미끄러져 내려감


전략 게임용 controlled movement를 사용한다.

============================================================
21. 건물 스케일
============================================================

모든 건물은 일관된 world scale을 사용한다.

이전 구현에서 발생했던 다음 문제는 절대 허용하지 않는다.

"건물이 산과 비슷한 크기로 생성됨"


스케일 관계는 반드시:

PERSON << BUILDING << MOUNTAIN

이어야 한다.


대략적인 상대 개념:

사람
≈ 기준 크기

작은 집
≈ 사람 높이 몇 배

일반 건물
≈ 작은 집보다 조금 큼

대형 시설
≈ 일반 건물보다 큼

산
≈ 건물보다 압도적으로 큼


정확한 숫자는 현재 월드의 실제 scale을 검사한 뒤 결정한다.

임의로 모델마다 scale = 100 등의 값을 넣지 않는다.

24. 도로

- 군대 이동

도로 역시 지형을 무시하면 안 된다.

28. 플레이어 공격
============================================================

플레이어 군인도 반드시 적을 공격할 수 있다.

이전처럼:

AI 공격 가능
PLAYER 공격 불가능

상태가 발생하면 안 된다.


플레이어 유닛과 AI 유닛은
같은 Combat System을 사용한다.


============================================================
29. AI 공격
============================================================

AI 군인 역시 동일한 전투 규칙을 사용한다.

AI에게 특별한 공격 함수나
강제 피해 코드를 주지 않는다.


============================================================
30. 전투
============================================================

기본 공격 절차:

1. 공격 명령 수신
2. target 확인
3. target이 살아 있는지 확인
4. 적대 관계 확인
5. 공격 범위 확인
6. 범위 밖이면 접근
7. 범위 안이면 공격
8. cooldown 적용
9. damage 적용
10. target 사망 여부 확인


============================================================
31. 산과 전투
============================================================

산 반대편의 적을
단순 거리 계산만으로 공격하면 안 된다.

필요한 경우:

- line of sight
- terrain raycast
- obstacle check

를 사용한다.


예:

Soldier A

████ MOUNTAIN ████

Soldier B


직선 공격:

불가능


============================================================
32. PLAYER와 AI 규칙 동일성
============================================================

가장 중요한 시스템 원칙 중 하나이다.

PLAYER와 AI는 동일한 게임 세계에 존재한다.

AI만 특별한 규칙을 사용하지 않는다.


AI에게 다음 치트를 주지 않는다.

- 산 통과
- 호수 통과
- 바다 보행
- 순간 이동
- 무한 공격 사거리
- 벽 관통 공격
- 즉시 건설
- 무한 병력
- 무한 자원
- 이동 속도 치트
- 건설 거리 무시
- 플레이어에게 없는 명령


============================================================
33. AI
============================================================

AI는 단순히 플레이어를 향해 달려드는 적이 아니다.

AI는 하나의 국가를 운영한다.


향후 AI가 수행해야 하는 행동:

- 도시 개발
- 건설
- 군대 생산
- 국방
- 영토 확장
- 외교
- 전쟁
- 평화
- 기반시설 건설


단:

1차 구현에서 모든 AI 기능을 동시에 만들 필요는 없다.

전쟁 상태는 양방향으로 일관되게 적용해야 한다.


중립국을 군인이 자동 공격해서는 안 된다.

49. Delta Time
============================================================

movement와 simulation은 frame-dependent 하게 작성하지 않는다.

잘못된 예:

position += speed


올바른 개념:

position += speed * deltaTime


단,
현재 프로젝트의 update architecture를 우선 분석한다.

FAIL:

유닛이 수직으로 산을 올라간다.

============================================================

호수 반대편에 이동 명령.

FAIL:

물을 걸어서 건넌다.

집을 하나 건설한다.

유닛보다 크고,

FAIL:

getTerrainNormal()

getSlope()

isWalkable()

목적:

월드 생성기를 수정하지 않고
게임 시스템이 필요한 terrain 정보를 읽을 수 있게 한다.


============================================================
73. 구현 전 해야 할 일
============================================================

실제 코드 작성 전에:

1. 프로젝트 파일 구조를 확인한다.
2. 월드 생성 관련 파일을 식별한다.
3. 월드 생성 코드는 수정 금지 영역으로 취급한다.
4. terrain data에 접근할 수 있는 기존 방법을 찾는다.
5. 기존 camera/input 코드 확인.
6. 기존 object/entity architecture 확인.
7. 이후 구현 계획을 세운다.


바로 대규모 코드를 작성하지 마라.


============================================================
74. 구현 방식
============================================================

한 번의 작업으로 게임 전체를 완성하려 하지 않는다.

각 PHASE를 순서대로 구현한다.

각 PHASE마다:

IMPLEMENT
↓
TEST
↓
FIX
↓
VERIFY

과정을 수행한다.


이전 PHASE에 심각한 오류가 남아 있으면
다음 PHASE로 넘어가지 않는다.

75. 최종 핵심 원칙
============================================================

1.

현재 월드 생성기는 완성품이다.

건드리지 않는다.


2.

보이는 지형은 실제 게임 규칙에도 존재한다.


3.

산은 관통할 수 없다.


4.

물은 육상 유닛이 걸어서 건널 수 없다.


5.

PLAYER와 AI는 동일한 규칙을 사용한다.


6.

PLAYER와 AI는 동일한 이동 시스템을 사용한다.


7.

PLAYER와 AI는 동일한 전투 시스템을 사용한다.


8.
