# 자동화 워크플로 v0.2

자동화 그룹의 **워크플로 편집기**, **자동화 실행 기록**, **자동화 관리**에서 사용합니다.

## PNG → WEBP 자동화 시작

1. 기본 **간편 모드**의 이미지 예제에서 `파일 감시`를 선택하고 입력 폴더를 설정합니다. `파일 감시 → 조건 → 변환 → 이동` 네 단계가 표시됩니다.
2. `변환`에 중간 출력 폴더를, `이동`에 최종 출력 폴더를 지정합니다. 입력 경로는 앞 단계에서 자동으로 전달됩니다. 입력 폴더와 출력 폴더는 구분하세요. 출력 폴더가 감시 폴더의 하위인 경우 해당 폴더는 감시에서 제외됩니다.
3. 각 설정의 **설정 적용**을 누르고 검증 결과가 `실행 가능`인지 확인합니다.
4. **실행**에서 PNG 파일을 선택해 테스트합니다. 원본은 보존됩니다.
5. **저장** 후 자동화 관리에서 해당 워크플로를 선택하고 **활성화**합니다.
6. 입력 폴더에 새 PNG를 넣으면 WEBP로 변환하고 최종 폴더로 이동합니다. 실행 결과와 오류는 실행 기록에 남습니다.

앱이 실행 중일 때만 감시합니다. 활성화 전에 존재하던 파일과 기존 파일의 수정은 처리하지 않습니다. 1초 간격으로 검사하며 크기와 수정 시간이 두 번 연속 같은 새 파일을 처리합니다. 매우 천천히 복사되는 파일은 복사가 끝나기 전에 감지될 수 있습니다. 실패한 파일은 실행 기록을 확인하고 편집기의 테스트 실행으로 재시도하세요.

## 편집

- 라이브러리 검색 후 노드를 더블 클릭하거나 **노드 추가**를 누릅니다.
- 노드를 드래그해 이동합니다. 간편 모드에서는 노드 출력 연결점을 다음 노드나 입력 연결점으로 드래그하면 실행 흐름과 호환되는 데이터가 함께 연결됩니다.
- 고급 모드의 파란 포트는 실행 흐름, 초록 포트는 데이터입니다. 실행 포트를 연결해도 데이터가 자동 연결되며, **연결 시 데이터 자동 연결**을 끄면 포트별로 직접 연결할 수 있습니다.
- 우클릭 드래그로 캔버스를 이동하고 휠로 확대·축소합니다.
- Ctrl+S 저장, Ctrl+Z/Y 실행 취소·다시 실행, Ctrl+D 복제, Delete 노드/연결 삭제를 지원합니다.
- 조건 노드는 `true`와 `false` 중 한 경로만 실행합니다. 데이터 연결만으로 노드가 실행되지는 않습니다.
- 합류 노드는 활성화된 선행 노드 처리 후 실행당 한 번 실행합니다. 실행되지 않은 분기의 데이터를 요구하면 오류가 기록됩니다.
- 필수 경로가 비어 있거나 연결이 부족한 편집 중 그래프도 저장할 수 있지만, 검증을 통과해야 실행/활성화할 수 있습니다.
- 저장하면 기존 감시는 비활성화됩니다. 변경 내용을 확인한 뒤 관리 화면에서 다시 활성화하세요.
- 가져온 파일은 새 ID로 복사되며 비활성화됩니다. 알 수 없는 노드 타입은 그대로 보존하고 실행을 차단합니다.

## 간편 모드와 고급 모드

간편 모드의 라이브러리는 파일 감시·조건·변환·이동을 제공합니다. 파일 입력 포트는 숨기고 앞 단계 결과를 자동 사용하며, 입력/출력 폴더와 이미지 형식 등 필요한 설정만 표시합니다. 조건은 항상 참/거짓, 파일 확장자·존재 여부·크기를 편집할 수 있습니다.

고급 모드에서는 전체 노드 라이브러리, 개별 실행/데이터 포트, 수동 입력, TRUE/FALSE 분기, 내부 복합 조건을 편집합니다. 기존 복합 조건과 다른 종류의 노드는 간편 모드에서도 보존되며 고급 모드에서 편집하도록 안내합니다. 모드 전환은 그래프를 재구성하지 않고 편집 중인 설정을 적용하며, 앱의 기존 설정 파일은 변경하지 않습니다. **전체 보기**로 캔버스의 모든 노드를 맞춰 볼 수 있습니다.

## 스마트 연결과 설정 추론

노드 연결 시 비어 있는 데이터 입력을 호환되는 출력과 함께 연결합니다. 가까운 실행 선행 노드를 먼저 확인하고, 입력 이름과 표준 파일 출력 이름 및 타입을 비교합니다. Condition처럼 파일을 출력하지 않는 노드는 실행 선행 노드의 파일을 찾아 전달합니다. 따라서 `변환 → 이동`을 연결하면 이동의 입력은 변환의 실제 결과 파일이 됩니다. 뒤쪽 연결을 먼저 만들었더라도 앞쪽 노드를 연결하면 누락된 데이터 연결을 보완합니다.

기존에 직접 연결한 단일 입력과 숫자 비교 기준 같은 수동 상수는 유지합니다. 후보가 동등하면 임의로 고르지 않고 로그에 안내하며, 고급 모드에서 직접 선택할 수 있습니다. 파일 목록 입력은 여러 공급자를 연결할 수 있고 저장된 연결 순서대로 수집합니다. 조건 형식을 바꿔 새 입력 포트가 생겨도 자동 연결을 보완합니다.

한 번의 스마트 연결은 실행선과 데이터선을 함께 실행 취소·다시 실행합니다. 실행선을 삭제하면 해당 연결이 만든 자동 데이터선도 정리합니다. 간편 모드에서 보이는 선은 두 노드 사이 연결 묶음이므로 직접 만든 데이터 연결도 함께 삭제하며, 고급 모드에서는 직접 만든 데이터선을 별도로 유지합니다.

## 연결값 자동 전달

데이터 연결이 있으면 선행 노드의 실제 출력값을 사용합니다. 입력 경로를 다시 지정할 필요가 없으며 속성 패널에는 **자동 전달 ← 노드.포트**로 표시됩니다. 연결이 없으면 직접 입력한 값, 그다음 노드/조건 형식의 기본값을 사용합니다. 연결된 선행 노드가 실행되지 않았다면 수동값으로 대체하지 않고 오류를 기록합니다.

이미지 변환에서 `sample_1.webp`를 생성했다면 파일 이동에도 그 경로가 전달됩니다. 최종 출력 폴더에 같은 이름이 있으면 이동 결과도 새 이름을 사용하고, 이후 노드에는 이동 후 실제 경로가 전달됩니다.

| 입력 포트 | 연결 정책 |
| --- | --- |
| 실행 Flow | 복수 연결, 활성 선행 노드 뒤에 실행당 한 번 합류 |
| String / Number / Boolean / FilePath 등 단일 값 | 연결 1개 |
| FileList | 복수 연결, FilePath 또는 FileList 출력 허용 |
| Condition 내부 입력 | 각 조건 형식이 선언한 타입과 연결 정책 |

**파일 목록 합치기** 노드는 여러 파일 경로와 파일 목록을 받습니다. 저장된 `connections` 배열 순서대로 값을 모으고 FileList를 한 단계 펼칩니다. 중복 경로는 유지합니다. 실행 순서는 실행/데이터 의존성을 함께 고려한 위상 순서이며, 데이터 공급자는 실행 흐름의 앞에 있어야 합니다. 목록 수집 순서는 실행 완료 순서와 무관합니다. 데이터 연결만으로 실행을 시작하지 않습니다.

## Condition 내부 조건 편집

고급 모드 라이브러리의 **Condition · 통합 조건** 노드를 추가합니다. 기본 조건은 항상 참입니다. 선택한 노드 오른쪽의 조건 편집기에서 조건 형식 블록을 삽입하거나 삭제하고 형식과 비교 연산자를 선택하세요.

| 조건 형식 | 동적 데이터 입력 | 설정 |
| --- | --- | --- |
| 항상 참 / 항상 거짓 | 없음 | 없음 |
| 파일 확장자 비교 | file_path: FilePath | extension, eq / ne (대소문자 무시) |
| 파일 존재 여부 | file_path: FilePath | exists / missing (일반 파일 여부) |
| 파일 크기 비교 | file_path: FilePath, threshold: Number | eq / ne / lt / le / gt / ge, 기준 크기는 바이트 |
| 문자열 비교 | a: String, b: String | eq / ne / contains / starts_with (대소문자 구분) |
| 숫자 비교 | a: Number, b: Number | eq / ne / lt / le / gt / ge |
| Boolean 검사 | value: Boolean | is_true / is_false |

외부 입력 포트 이름은 `조건블록ID.입력명`입니다. 예를 들어 `c_123.file_path`는 `c_123` 내부 조건의 파일 입력입니다. 내부 조건은 캔버스의 Condition 노드 안에도 카드로 표시되며 자체 실행 흐름을 만들지 않습니다. Condition의 실행 입력은 `flow_in`, 실행 출력은 `true`/`false`이며 `result`는 최종 Boolean 데이터 출력입니다.

1. PNG 조건을 선택한 뒤 **파일 크기 비교** 블록을 추가합니다.
2. 자동으로 연결된 파일 입력을 확인합니다. 자동 연결을 껐다면 폴더 감시의 `file_path`를 두 조건 블록의 `file_path` 포트에 각각 연결합니다. 수동 경로는 필요하지 않습니다.
3. 파일 크기 연산자는 `le`, threshold는 `10485760`으로 설정합니다.
4. 내부 조건식의 AND 그룹으로 두 조건을 결합합니다. PNG이며 10MB 이하인 파일만 `true` 분기로 진행합니다.

조건식 트리에서 하위 식을 선택한 뒤 **AND/OR/NOT 감싸기**로 중첩할 수 있습니다. 그룹을 선택하고 **그룹 변경**으로 연산자를 바꿉니다. NOT은 하위 식 1개만 허용합니다. **감싸기 해제**는 하위 식이 하나인 그룹을 제거합니다. 블록 추가는 선택한 AND/OR 그룹에 삽입하며, 단일 조건을 선택했다면 두 조건을 AND로 묶습니다. 삭제 시 해당 참조와 연결만 정리합니다. 조건은 최소 1개, 최대 64개이며 조건식 중첩은 최대 16단계입니다.

AND/OR는 왼쪽부터 단락 평가합니다. 결과가 확정되면 뒤쪽 조건의 입력을 조회하지 않습니다. 정적 검증에서는 모든 내부 조건의 형식·연결·필수 입력 선언을 검사하며, 실행 시에는 실제 평가하는 조건의 값만 조회하고 타입을 검사합니다. Number는 문자열이나 Boolean을 자동 변환하지 않습니다. 0, False, 빈 문자열은 각각 유효한 숫자·Boolean·문자열 값입니다.

형식을 바꾸면 입력 포트가 갱신됩니다. 이름과 타입이 같은 연결 및 수동값은 유지하고, 호환되지 않는 연결은 목록을 안내한 뒤 해제합니다. 이 변경도 Ctrl+Z/Y로 되돌리거나 다시 적용할 수 있습니다.

**조건 결과 미리보기**는 파일 변경 작업을 실행하지 않습니다. 연결 입력은 현재 그래프와 일치하는 최근 테스트 실행의 출력값을 사용합니다. 출력값이 없거나 그래프를 수정했다면 먼저 테스트 실행해야 합니다. 연결이 없는 값은 현재 편집 중인 수동값과 기본값으로 평가합니다.

## 저장 구조와 구버전 호환성

외부 JSON의 `schema_version: 1`은 유지합니다. 새 노드 타입은 `logic.condition`이며 내부 블록·설정·식은 노드의 `config`에, 외부 입력 매핑과 TRUE/FALSE 실행 연결은 기존 `connections`에 저장합니다.

```json
{
  "id": "condition_1",
  "type": "logic.condition",
  "position": [300, 100],
  "config": {
    "blocks": [
      {"id": "extension", "type": "file.extension", "config": {"extension": "png", "operator": "eq"}},
      {"id": "size", "type": "file.size", "config": {"threshold": 10485760, "operator": "le"}}
    ],
    "expression": {"op": "and", "children": [{"block": "extension"}, {"block": "size"}]}
  }
}
```

연결 예: `trigger.file_path → condition_1.extension.file_path`, `trigger.file_path → condition_1.size.file_path`. 내부 식의 `block` 참조는 일반 노드/실행 연결과 별개입니다.

기존 `logic.extension`을 읽으면 같은 ID의 `logic.condition`으로 메모리에서 변환합니다. `flow`는 `flow_in`, `source_path`는 `legacy_extension.file_path`로 매핑합니다. 기존 `file_path` 출력과 수동 경로·설정도 보존합니다. 원본 파일은 읽기만으로 덮어쓰지 않으며 사용자가 저장할 때 변환된 구조를 기록합니다. v0.1 실행 기록 DB와 안전 정책은 그대로 사용합니다.

알 수 없는 조건 형식은 내부 설정·식·연결을 삭제하지 않고 저장합니다. 사용 불가 오류를 표시하고 테스트 실행 및 자동 활성화를 차단합니다. `ConditionRegistry.register(ConditionSpec(...))`로 형식을 추가할 수 있고, 동적 포트·검증·평가·편집 UI가 같은 레지스트리를 사용합니다.

## 저장과 실행 정책

워크플로: `user_data/automation/workflows/*.workflow.json`.
실행 기록: `user_data/automation/runs.sqlite3` (시각은 UTC 저장, 화면에는 현지 시각).
기존 앱 설정과 TC 잔액은 자동화에서 변경하지 않습니다.

실행은 단일 백그라운드 워커에서 순차 처리하며 대기열은 256건입니다. 대기열이 가득 차면 감시 이벤트는 다음 검사 때 다시 시도합니다. 최대 200개 노드, 2000개 연결, 실행 제한 시간 300초입니다. 시간 제한과 중지는 노드 사이에서 확인하며 이미 시작된 파일 작업은 마무리한 뒤 중지합니다. 실행 중지는 현재 실행과 대기 작업을 취소하지만 감시는 유지합니다. 새 이벤트도 중단하려면 비활성화하세요.

기존 출력 파일은 `_1`, `_2` 등의 이름으로 보호합니다. 이미지 변환과 복사는 임시 파일을 완성한 뒤 교체합니다. 실행 실패 시 이전에 완료된 노드의 파일 작업을 되돌리지 않습니다. 앱 종료 중 처리 중이던 기록은 다음 시작 시 `interrupted`로 표시하고 자동 재실행하지 않습니다.
